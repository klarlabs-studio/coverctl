Works with **all sorts of languages** — Python, TypeScript/JavaScript, Java, Rust, Go, C#, C/C++, PHP, Ruby, Swift, Dart, Scala, Elixir, Shell — same domains and MCP tools. Mock-heavy or exotic layouts may need an explicit `domains:` block — see [trust calibration](/coverctl/quick-start/#where-coverctl-works-best-and-where-it-may-need-adjustments).

coverctl is **not** `go tool cover` or a Go-only cover CLI — it is policy + MCP over each language's native runner. See [coverctl vs native commands](/coverctl/compare/coverctl-vs-native/).

## A real agent session

After `coverctl mcp serve` is wired into Claude Code. *Rendered for clarity — your client may format tool-calls differently.*

<div class="agent-transcript-chrome" aria-hidden="true">

  <span class="dot dot-y"></span>

  <span class="agent-transcript-title">claude code · coverctl</span>

```text
You:    Add the email-validation feature to the api domain.

Claude: I'll add EmailValidator + tests under src/api/.

  [edits: src/api/email.ts, src/api/email.test.ts]

  Tool call → coverctl check
  Result   → passed: false; failing: api (78.2%, required 80%)
             uncovered: src/api/email.ts:42-58 (error paths)

  Tool call → coverctl suggest api
  Result   → uncovered files: email.ts (16 lines), retry.ts (4 lines)

  Two error branches in EmailValidator.validate are uncovered.
  I'll add cases for empty-input and malformed-domain so api meets
  the 80% threshold before we commit.
```

</figure>

The regression that used to surface in CI 8 minutes later is fixed in the same agent turn.

<Aside type="caution" title="Watch for these agent failure modes">

- **Threshold lowering as a "fix"** — agents proposing edits to `.coverctl.yaml` to drop a domain's `min:`. That's not a fix.
- **Hallucinated coverage numbers** — claiming coverage rose without re-running `coverctl check`.
- **Ignoring rejection codes** — retrying the same input after a structured rejection. The `remediation` field tells the agent what to change.

coverctl returns deterministic structured signals; the agent's *fix* still needs a human reading.

</Aside>

## Why not your current setup?

| Today | Why it fails for agent-edited code |
|---|---|
| **Red-CI agent loop** (status quo) | Agent edits → tests fail in CI 8 minutes later → context lost. coverctl: feedback in seconds, in the same turn. |
| **Codecov / Coveralls dashboards** | Post-merge visibility for humans. coverctl: pre-commit signal for agents. |
| **Native runners** (`go test -cover`, `pytest --cov`, `nyc`, …) | Substrate only — one language, no domain policy, no MCP. coverctl **uses** them; it does not replace Go cover or become a Go-cover wrapper. [Comparison →](/coverctl/compare/coverctl-vs-native/) |

## Quick Start

<LinkCard
  title="Wire coverctl into Claude Code, Cursor, or Cline →"
  description="Connect through MCP. Agent calls check, suggest, debt directly inside the edit loop, before commit. Most users start here."
  href="/coverctl/quick-start-agent/"

Working from a terminal instead? [Terminal quickstart →](/coverctl/quick-start/)

```bash
# Install
brew install klarlabs-studio/tap/coverctl   # or: go install go.klarlabs.de/coverctl@latest

# One-time project setup
coverctl init

# Then either run from terminal:
coverctl check

# ...or wire into Claude Code / Cursor / Cline (default agent mode)
# and let the agent invoke coverctl during editing.
```

## Four moves that make this a category, not a feature

<div class="editorial-cards">
<CardGrid>
  <Card title="Pre-commit, not post-CI" icon="approve-check">
    Coverage feedback in the agent's edit turn — before the diff lands in CI. The wedge metric is regressions caught pre-commit, not coverage percent.
  </Card>
  <Card title="Agent-callable through MCP" icon="puzzle">
    Speaks MCP — the multi-vendor agent-tool standard governed by Anthropic, OpenAI, Google, Microsoft, AWS. Works with every MCP-capable client today; works with whatever ships next.
  </Card>
  <Card title="Polyglot governance, one config" icon="laptop">
    One `.coverctl.yaml` enforces per-domain thresholds across Go, Python, TypeScript, Rust, Java, C#, C/C++, PHP, Ruby, Swift, Dart, Scala, Elixir, Shell.
  </Card>
  <Card title="Local-first, hardened boundary" icon="shield">
    No SaaS account, no source upload, no third-party dependency in the agent's reach. Input + output sanitization defends against prompt-injection through test-runner flags and hostile filenames.
  </Card>
</CardGrid>
