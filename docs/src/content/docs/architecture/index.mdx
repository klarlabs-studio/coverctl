coverctl follows strict onion DDD: dependencies point inward. Agents and
humans share one application service; MCP and CLI are thin adapters.

## Layers (short)

| Layer | Package | Owns |
| --- | --- | --- |
| Domain | `internal/domain` | Coverage stats, policy evaluation, value objects |
| Application | `internal/application` | Check / report / debt / suggest / compare orchestration |
| Infrastructure | `internal/infrastructure` | Runners, parsers, config, history, PR clients |
| CLI | `internal/cli` | Flags, formatters, golden-path output |
| MCP | `internal/mcp` | Tool surface, input + output sanitization, rejection schema |
| Eval | `internal/eval` | Adversarial + happy-path scenario corpus |

Import fitness tests in `internal/architecture/` enforce the boundaries
in CI. God-file ceilings prevent `cli.go` / `service.go` / `server.go`
from growing without extraction.
